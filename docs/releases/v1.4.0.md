# SessionGuard 1.4.0

`1.4.0` focuses on release signing and direct-download trust.

## Highlights

- added standard Authenticode signing support for official release automation
- signed the root installer scripts inside the published setup bundle
- added release-time signature verification for app, service, and setup-bundle installer entry points
- kept the published SHA256 checksum asset as the primary download trust signal even after adding release signing

## Included in this release

- new `scripts/signing/common.ps1`
- new `scripts/signing/Verify-SessionGuardReleaseSignatures.ps1`
- signing support in:
  - `scripts/app/Publish-SessionGuardApp.ps1`
  - `scripts/service/Publish-SessionGuardService.ps1`
  - `scripts/install/Publish-SessionGuardBundle.ps1`
  - `scripts/release/Publish-SessionGuardReleaseAssets.ps1`
- release workflow updates in `.github/workflows/release.yml`
- updated README, getting-started, runtime-model, manual-validation, development, limitations, roadmap, and changelog docs

## Architecture

- official tag releases can now require a configured Authenticode signing certificate in automation
- local builds still work unsigned unless signing is explicitly requested
- published manifests now record both signature status and signing configuration metadata
- the setup zip checksum asset remains part of the release contract and is still the primary direct-download trust anchor

## Limitations

- local and custom builds may still be unsigned
- SmartScreen reputation can still lag even on signed releases
- EV signing remains an operational choice outside the repo rather than a code requirement
