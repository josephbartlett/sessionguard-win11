# SessionGuard 1.3.0 (Draft)

This is a draft release note for unreleased packaging and trust hardening work that exists on `main` but is not currently represented by a public `v1.3.0` tag.

Packaging and distribution hardening release focused on making the direct-download setup path easier to verify and safer to trust.

## Highlights

- published SHA256 checksum assets for setup, app, service, and source downloads
- added extracted-bundle verification through `Verify-SessionGuard.ps1`
- updated the combined installer to verify bundle integrity before install by default
- added Authenticode signing support for official release automation
- signed the root installer scripts inside the published setup bundle

## Included in this release

- new `scripts/install/Verify-SessionGuardBundle.ps1`
- new root-level `Verify-SessionGuard.ps1` inside the published setup bundle
- new `scripts/signing/common.ps1`
- new `scripts/signing/Verify-SessionGuardReleaseSignatures.ps1`
- bundle integrity inventory at `bundle-integrity.json`
- expanded `release-assets.json` with file sizes, SHA256 hashes, and published-component trust metadata
- new `sessionguard-win11-sha256-<version>.txt` release asset
- updated README, getting-started, runtime-model, development, limitations, manual-validation, changelog, and roadmap docs

## Architecture

- the product runtime model stays the same: service-backed monitoring with a tray-first desktop shell
- trust reporting is now part of the publish pipeline rather than an external ad hoc step
- official tag releases can now require a configured Authenticode signing certificate in automation while local builds can still be left unsigned
- the published setup zip checksum remains the primary download trust anchor, while extracted-bundle verification reports consistency and current signature status after extraction

## Limitations

- `1.3.0` does not add an MSI installer; the preferred install path is still the setup zip plus `Install-SessionGuard.ps1`
- local or custom builds may still be unsigned and can still trigger SmartScreen or other Windows trust prompts
- extracted-bundle verification is not a replacement for the published setup zip checksum
- this release improves trust and install ergonomics, not Windows restart coverage itself
